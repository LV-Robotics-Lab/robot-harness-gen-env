## 新前端做了什么（对着你提的两点）

1. **"明确看到生成到哪一步"**：顶部横向 stepper，7 步各显示 ✔完成/⟳进行中/⏭跳过/⛔阻塞/✕失败 + 每步耗时；进行中的步有实时跳动的秒表；页头有整体已运行时长；浏览器标签页标题也会变（切去别的窗口也能瞄到进度）。阶段状态由服务端统一计算（产物文件时间 + 日志全文标记），修掉了旧版"带缺口引进的 run 第①步永远显示没完成"的误导。
2. **"直接看到每一步的输出"**：点击任一步看该步专属面板——①覆盖表格、②候选资产 chips（绿=选中、红=拒绝+原因码）、④质检截图廊、⑥场景对象表+场景文件一键预览（含 generated_scene.py）、⑦渲染视频大图+各视角带中文标注（观察·起始/中段/结束、俯视、分割图、世界左右）+runtime 校验结果。另有"产物文件"面板可浏览/预览 run 目录全部文件。
3. **运行中不被打断**（旧版最大硬伤）：旧版每 1.5 秒整页重绘，展开的内容全部被重置；新版分区域增量更新，实测连续多个轮询周期里，手动选中的阶段不被抢走、展开的 JSON 保持展开、日志只追加。
4. **日志可用了**：常驻底部、增量加载完整日志（不再只有尾 100 行）、错误红/通过绿、阶段分隔线、连续重复行折叠（渲染阶段几十行同样的 OIDN 报错折成一行 ×N）、"跟随"开关（手动上滚自动暂停跟随）。

## 事件三段式

1. **重启服务时 ssh 连接被误杀** → README 里的 `pkill -f web/app.py` 在 ssh 里执行时会连带匹配到携带同样字符串的远程 shell 自身（交互式手敲没这问题）→ 我改用不自匹配的正则重启，未改你的文档；对结果无影响。
2. **回放模拟器暴露时间轴 bug**：复制的测试产物带着旧文件时间，某阶段耗时显示成 39 分钟（实际总长 46 秒）→ 服务端加了两道防线（早于 run 开始的文件时间不参与时间轴；单阶段耗时不得超过总耗时），并把③④的耗时改用更符合真实时序的独立锚点；补了测试，9/9 绿 → **已回灌 web 层代码本身**，真实 run 与历史 fixture 都不会再出现离谱耗时。
