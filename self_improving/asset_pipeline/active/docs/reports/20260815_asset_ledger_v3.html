env-gen-dev · 资产管线 · metadata 契约定稿

从「一个下载/生成的资产」到「可检索、可跨仿真器迁移的账本」：asset_ledger.v3

四路 subagent 对抗辩证 + 两组实验裁决 + 79 份账本全量迁移的定稿记录。页面上所有数字来自真实运行，不需要读代码。

1 · 这是什么

一句话：这是资产入库 metadata 契约（每个资产一份 ledger.json）的 v3 定稿——回答"一个资产（网络下载的或我们自己生成的）入库时要记下哪些事实，才能支撑高效检索与跨仿真器迁移，且一个多余字段都不留"。

做法不是开会拍脑袋：四个带真机只读访问的 subagent 各执一个立场互相攻击（检索充分性怀疑者 / 迁移充分性怀疑者 / 冗余审计员 / 外部对标员），产出的每条主张都要配代码行号或实跑数字；争议不下的用两组真实实验裁决（E1 检索消融重跑 44 条矩阵、E2 Isaac 编译+运行时实跑）；定稿后 79 份存量账本自动迁移、双测试套件全绿收工。

吃什么→吐什么：输入 = v2 契约（~80 字段）+ 全部真实消费代码 + 79 份存量账本 + 两天来的实测数据。输出 = lib/ledger.py（v3 契约与校验器，常量表即契约）+ 迁移后的 79 份 v3 账本（git 管辖）+ 决策记录 docs/2026-08-15-asset-ledger-v3-decision-record.md + 本页。

表示层representations[]{format,uri,backend,role,sha256} · 新 frame{up_axis} · geometry_state{scale_baked} · files[]? · collision_meta?usd_enrich 按 backend/role 选表示；scale 中和以 scale_baked 声明为前提；sha256 承载身份与验证防漂移E2：无声明时的无条件中和让 cracker box 在 Isaac 大 2.8527×（=1/scale，30 个 model 命中）
来源/许可source{kind 分支: retrieved/generated} · license{spdx,status,…attribution?}(library,group,file) 三元组做幂等去重键；license-gate 过滤；分支互斥校验抓半改的复制粘贴许可条款页会消失——不入账即永久失据（不可恢复捕获铁律）
验证记录verification[]{backend,check,verdict,run_id,timestamp,verified_digest}usable 由此推导（禁手写）；latest-per-(backend,check)；digest 防旧网格的 pass 带新网格入库2026-08-14 数据事故中，17 份在 git 的账本是资产池唯一幸存部分——验证记录就是重建的底气
贯穿 v3 的一条硬规则（本周最贵的教训）：物理测量值是 资产 × 测量栈 的属性，不是资产的固有属性——同一个网格换了加载器，停留高度差 9mm。所以 v3 里任何实测块（姿态/腔体/颜色）都必须带 measured_against{backend, run_id}，校验器强制。迁移到新后端时这些数字不能照搬，要按该后端重测——测量脚本全部可续测，重测约 1 小时 GPU。

5 · 真实 case：一个字段的生与死

case A：一个字段怎么死——semantic_name

冗余审计员实测：79/79 份账本 semantic_name == category，无一例外
grep 全部六个消费面：命中仅契约自身+写入方；上游 grounding 读的是 catalog 的
  semantic_name，而 catalog 的这个字段由目录名派生——账本→catalog 通路不存在
删除后：262 测试全绿；catalog 照常生成 ── 判定：死字段，v3 删除

case B：一个字段怎么生——geometry_state.scale_baked

迁移怀疑者主张：GLB(已烘 scale) 与 USD(未烘) 是几何上不同的物体，契约无字段区分
E2 实跑：303_box 账本 scale=0.35054，源 USD bbox / GLB bbox 三轴比值
  = 2.8527170473137407 ≡ 1/scale（分毫不差）
  compile 后 Isaac 舞台实测 box 最大边 0.2134m vs 真值 0.0748m
  影响面账本实扫：52 个 model scale≠1，其中 30 个带 isaacsim 表示
修复实跑：scale 中和改以 scale_baked 声明为前提 → 尺寸正确 ── 判定：实证必需，v3 新增

6 · 为什么不那样做（一行式否决表）

被否方案实测死因
CLIP embedding 向量进账本随检索模型版本漂移，进契约=把 schema 和模型耦合；业界（Objaverse-XL）也是当数据集交付物发布 → 放契约外 sidecar 向量库
接触求解器参数（solref/kp/kd…）进账本引擎调参不是物体属性，跨后端不可迁移；GSO/YCB 均不记 → 归后端 profile
grasp/affordance 标注进账本ACRONYM 每 (object,scale) 存 2000 条——量级与 gripper 依赖注定是伴生数据集，不是元数据
形状/尺寸派生量（h/w 比等）入库可从 mesh_bbox_m 投影时派生，存储即冗余；真正缺的是上游 parser/grounding 的消费（对齐清单）
删掉 inertial 整块（73 份全 null）外部对标：业界最小物理集含惯量主轴；null+status 是"引擎会推导"的诚实陈述 → 收缩为可选而非删除
保留 mass 的 runtime_default 对"runtime"是谎言：真实运行时质量走上游 catalog 标量通路；86/87 份抄同一常量 0.1；唯一读者是 archive 死代码
撤销微晃资产（panel/ceiling/teddy）替换采购全卡入库物理门，类目直接消失——1-3° 微晃优于类目不可用（保留+对齐清单）

坑现象 → 真凶

9 · 收尾：术语与位置

账本(ledger)=每资产一份的权威入库记录，git 管辖。fragment=账本派生的场景生成视图（yaml）。catalog=上游扫描 shadow 树产出的运行时目录。grounding=把 prompt 里的物体请求匹配到目录条目的上游模块。IR=openxsim 的后端中立中间表示。measured_against=实测数据必须携带的"在哪个栈上测的"戳。

位置：契约 self_improving/asset_pipeline/active/1_asset_reuse/lib/ledger.py（hyx 分支 0df4fb4 + fb0e014）；决策记录 docs/2026-08-15-asset-ledger-v3-decision-record.md；迁移脚本 scripts/ledger/migrate_v3.py；轻量运行证据归档在 self_improving/validation_evidence/ledger_v3_20260815/。上游依赖：LV-Robotics-Lab/robot-harness-gen-env（scene_gen 上游只读）、RoboTwin canonical checkout（external/RoboTwin）。

字段级裁决卡（全量 45 条）与 E1 检索矩阵逐行对照（全量 44 条）

两组都是全量呈现非抽样。字段卡逐条给出处置、消费者证据与失败模式——这就是"metadata 定稿"的可审形态；E1 对照表给出模型级颜色接入前后每条 prompt 的真实变化。
